# 중간 프로젝트: 뱁새 발표 앱 (사용한 프롬프트와 결과)

- 앱 저장소: https://github.com/JangYurim0607/baepsae-presenter
- 도구: Claude Code(Sonnet 5.5), Electron, Claude API(비전·대본·발표체 변환)
- 캐릭터: 직접 만든 뱁새 캐릭터 시트 3장(안경 · 마이크 · 확성기) — `sheet-glasses.webp`, `sheet-mic.webp`, `sheet-megaphone.webp`

## 1. 처음 요청

> 마우스 커서를 따라다니는 뱁새가, 커서를 3초 이상 대면 그 화면 내용을 발표해 주는 앱. 욕설·폭력 등은 짹짹으로 바꾸고, 글을 읽을 땐 안경을 쓰고, 10초간 가만히 있으면 주저앉고, 캐릭터 시트를 잘라서 쓰고, Windows와 Mac에서 돌아가게.

**결과**: Electron 투명 오버레이 앱. 시트에서 스프라이트 17개를 잘라 방향·표정별로 연결했고, 커서 주변 화면을 Claude 비전으로 읽어 발표합니다. 욕설·개인정보는 `[짹짹]` 토큰으로 치환해 새소리로 재생합니다.

## 2. 목소리: 자연스럽게 말하기

> 인공지능 티가 나지 않는 20대 중반 여성의 발표 목소리로. 음정·속도를 후처리로 꾸미지 말고, 대본을 구어체로 바꾸고 의미 단위로 나눠서 문맥에 맞는 속도와 쉼을 정해라. 엔진은 갈아끼울 수 있게, 비교 청취 도구도 만들어라.

**결과**: 대본 → 발표체 변환 → 의미 단위 분할 → 속도·강도·쉼 계획 → TTS 엔진(맥 유나 / OpenAI / Google)의 파이프라인과, 블라인드로 듣고 점수를 매기는 비교 페이지(`npm run compare-voices`). 직접 들어 보니 어떤 엔진도 만족스럽지 않아 엔진이 한계라고 판단했고, 이 한계는 남겨 두었습니다.

## 3. 말투: 합쇼체 발표체

> 말하는 것도 "~에요"가 아니라 "~입니다"인 발표체여야 해.

**결과**: 대본 생성·변환·오류 문구를 모두 합쇼체로 통일하고, 해요체가 25% 넘게 섞이면 결과를 버리는 검증을 추가했습니다.

## 4. 발표 방식 바꾸기

> 커서를 대면 읽고만 있다가 클릭하면 발표해라. "~가 적혀 있습니다"가 아니라 그 주제를 직접 발표해라.

**결과**: 커서를 대면 0.4초 뒤 책을 펴고 백그라운드로 화면을 분석해 두고, 클릭하면 바로 발표합니다. 화면 묘사 표현을 금지하는 지침을 넣었습니다.

## 5. 포즈 랜덤 선택

> 학술적인 건 책, 재미있는 건 마이크, 심각하거나 청중이 꼭 알아야 하는 건 확성기를 든 모습으로 랜덤하게. 발표가 끝나면 뿌듯한 표정 5초. 커서를 대자마자 발표 준비를 하고 있게.

**결과**: Claude가 내용에 `tone`(academic, fun, serious)을 붙이고, 의미 단위마다 같은 종류 안에서 포즈를 바꿉니다. 시트 3장에서 포즈 18개를 `scripts/slice-poses.py`로 잘라 사용했습니다.

## 6. 중단과 질문

> 더블클릭하면 "앗 넵 그만할게요" 하고 그만해라. 질문은 뱁새를 우클릭하면 "질문이 있으시다고요?" 하며 마이크를 건네고, 머리 위에 작은 질문 창이 뜨게. 마이크로도 질문할 수 있게.

**결과**: 전역 마우스 훅으로 더블클릭을 감지해 합성·재생·진행 중인 분석을 모두 취소하고 "앗, 넵. 그만하겠습니다."라고 말합니다. 우클릭 질문은 뱁새 위에서만 클릭을 받도록 해서 구현했습니다. 마이크 질문은 앱 내장 음성 인식이 서버 연결 오류로 안 되어, 맥 받아쓰기(Fn 두 번)를 대신 눌러 주는 방식으로 바꿨습니다.

## 한계

- 목소리의 자연스러움은 만족스러운 수준에 이르지 못했습니다.
- Windows 빌드는 시험하지 못했습니다.
- 마이크 질문은 맥 받아쓰기에 의존합니다.
